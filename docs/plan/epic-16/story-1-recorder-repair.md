## Design and implementation order

### 1. Record writes without evaluating live geometry

`captureWriters.read` currently calls `computeWorldMatrix(force)` and `getBoundingInfo`; `quiet` suppresses recording, not side effects. `begin`, `write`, the enable observer and `checkpoint` use forced reads. `cursor-attribution-probe.pose` also computes live geometry. Audit the installed Babylon version for lazy getters on **all** these paths. Copy primitive local transform/parent, geometry extrema, camera/billboard, effective eligibility, thin slot/buffer and lifecycle operands at their owners. For a natural Babylon compute call invoke the original exactly once, preserve receiver, args, result and throws; copy the published result and already-existing cached bounds without invoking a getter that refreshes them. Distinguish authored changes from cached publications and unchanged checks. Do derived world/child/bounds work on detached scratch state, never by forcing or restoring the live cache. If a required operand cannot be read neutrally, record a named gap; do not substitute an idealized fresh matrix for a stale native one.

In `cursor-attribution-build.ts` instrument pinned diagnostic sources only. Inventory final writes in `enemyRendering.ts` (bar position, billboard and fill scale, separate effective enable), `socialRendering.ts` (sack rest **and** pass trajectory), `main.ts` (steed rig and floating votives/altar ember). Map parent writes to affected descendants in native order. Inspect **all** first-difference IDs: tick 179 has 14 health meshes and one sack; first pick has 50 differences including 26 steed meshes. These are leads, not an allowlist. Preserve door/chest, physics, pose, natural world/check, reparent, effective enable, thin edit/replace/upload and add/remove coverage; don't double-count nested wrappers or collapse intermediate writes.

Seed once at the first retained frame's actual start, not once per emptied queue; handle discarded pre-window frames explicitly. Independently enumerate the actual ordered scene at each existing advanced fixed step, pick (or no-pick presentation) and post-render boundary. Copy native cached observations **and authored inputs** there, independently of the event encoder, `last`, replay or occupancy. Match event cursor, phase, ray, identity, parent, eligibility, operands and observed world/bounds at each seam; report first divergent fields and missing/extra identities. Keep existing tolerance and conservative fallback/sweep rules. A missing cache with no defined neutral interpretation is not a match. Checkpoints may have their own lossless deltas against previous **checkpoint** data, not against writer predictions.

### 2. Replace post-`done` slicing with a finite live handoff

Use one ordered producer, one disk sink. Install a count-only Playwright binding before navigation. Encode immutable records (versioned seed/identity, frame begin, writer/checkpoint fragments, frame end, trailer) into fixed-size binary pages; intern repeated operands or reference the preceding per-ID value losslessly. Reserve space **before** copying, split large arrays into numbered fragments and preserve exact numeric precision. Prefer one filling page, one sealed page and one in flight; size pages from the software fixture and publish fixed byte/event/scalar limits, including encoder temporaries, transport encoding copies and decoder workspace. Aggregate resident writer data must respect the existing 500,000-event / 8,000,000-scalar guards; total persisted counts are separate. Bound seed/identity/active-scene state, partial-frame decode and error diagnostics too. Never accumulate a promise or callback per event/frame.

Send a sealed page asynchronously when credit is available; receiver verifies run/visit/sequence and length/hash, writes one compressed segment to a new run directory, atomically publishes it, then ACKs. No sync compression, awaiting I/O in fixed/render, simulation pauses, forced RAF, polling between game steps, or retries that discard writes. With no free space, immediately latch overflow, stop capture and identify last committed segment/frame. Persist the index incrementally, terminal totals and high-water marks. Receiver needs no unbounded pending queue. A segment arriving after failure cannot certify completion.

Use a pure typed transition function: `armed → producing` on first retained begin; window end seals the last frame and enters `draining`; only ordered final ACK plus validated trailer/window/counts makes `sealed`. Error, timeout, context loss or contamination in any nonterminal state makes `failed`; reject invalid events including premature completion. Disk/bridge/timeout effects belong in adapters. Render-loop stopped is **not** disk sealed or visit admitted. Bound final drain outside native capture. Always attempt `archiveNativeRows` before admission, including wait failure; keep incomplete segments marked partial and record page loss rather than reconstructing absent rows. Restore all hooks on success/failure/disposal.

### 3. Run scratch from the archive, not an array of traces

Remove `writerTrace()` post-run collection, `frames.push(...chunk)`, `traces.push(trace)`, whole-case JSON evidence strings and `scratch(traces)` from the hardware route. Extend `streamWriterReplay`/`writerReplay.step` with a bounded frame source and evidence sink. Stream one case, one bounded decoded frame (or bounded pieces of an oversize frame) and current seed/last state/populated buckets. Persist ordered frame evidence, demand and list comparisons as they are produced. Do not retain a query index per pick, all writes in `WriterReport.frames`, or reassemble them for validation/ledger output. Compare raw persisted records in order; compact manifest digests/counts locate evidence, not replace validation. Keep the eager implementation only as a small oracle if useful.

On the same hardware/browser **after** native count capture, feed scratch one bounded frame at a time from disk with acknowledgement before loading the next. One case/session at a time, no extra gameplay visit. Reuse `frameBlocks` semantics: contiguous blocks up to 240; repeat the whole block `floor(240/blockLength)` times, pad remaining slots with no demand, never oversample a prefix. For each repeat/arm restore seed and replay prior block prefix outside timers (or verify a bounded block-start state against prefix replay). For query work prepare the populated occupancy at the recorded pick cursor, not end-of-frame. Retain only that frame's prepared inputs. Warm both publish/query active and control, then three samples in existing alternating arm order; execute the same ordered operations and consume results. Accumulate coarse times for resident frame groups within each logical batch; keep clocks/loop boundaries symmetrical, no per-write clocks. Exclude archive I/O, decode, transfer, prefix restoration and evidence checks from both arms; **include** the actual bounds refresh, membership updates and populated walk/dedup/order in the active arm. Verify timer resolution supports demanded work or withhold rate. Preserve raw units, times, repeats/pad, consumed results, cold registration ms/size separately and existing largest full-active cost calculation, not active minus control.

### 4. Admission, ownership and file boundaries

- `tests/cursor-attribution-writers.ts`, `cursor-attribution-build.ts`, `cursor-attribution-probe.ts`: operand and independent snapshot adapters, count-only writer stream, neutral shared native sampling. `time` retains coarse pass timing; no writer hooks, transport, per-entry timers or scratch in native timing. Keep proxy sync, pass invocations, per-call work and times distinct; absent is `null`, not zero.
- `tests/cursor-capture-archive.ts` and a small shared protocol module: pure sequence/credit/window checks and manifest records; injected segment sink/source implemented by browser binding and Node filesystem. `cursor-publication-replay.ts`, `cursor-writer-evidence.ts`: incremental scratch session, injected batch clock and streaming report validation. No new gameplay statechart or general streaming framework.
- `tests/cursor-attribution.ts` wires adapters and reuses the existing run decision. Record attempted, captured, archived, validated and admitted stages separately. Advance completed visit counts only after required visit checks **including** `withVisit`'s post-work error/GPU checks return successfully; indicate separately if later cross-case scratch/ledger validation failed. Match each timing row against its count case's exact native tick span and sampled geometry/ray/hit, cue, list and work parity; no interpolation, dropping rows or fabricating ticks to offset recording overhead. Compare archived native rows incrementally where used across visits. Preserve raw partials even if `visitFrom` or a later check fails. Time-only and count-only fields must not be borrowed across arms.
- `tests/cursor-evidence.ts`: adapt evidence input shape only where necessary; retain the frozen arithmetic and calibration tests. No changes to production `src/`, pinned inputs, cadence, quality, visit budget or numerical gates. Compression alone, a larger cap, a mock sink, or a producer blocked on the consumer do not solve this defect.
