# EF0 follow-up 1 — Can we resolve a generation-time regression?

**Historical proposal; A/A reached preflight only.** It did not qualify timing. The user subsequently authorized EF1 and moved latency qualification to EF4 without changing the margins. See the [baseline decision](../../ef0-baseline.md#later-decision--generation-latency-moves-to-ef4) and [Epic 0 closeout](../../ef4-results.md#epic-0-delivery-closeout). The original proposed protocol follows.

## Why change the design?

[`batch()`](../../../tests/measure-generation.ts) discards two cycles, then calls `generateDungeon` ten times per seed in fixed rotation, timing each call before any allocation profiling. The parent takes nearest rank within process, then the median statistic across five fresh processes. For p95 that is rank `ceil(.95 × 10) = 10`: the window reports the third of five **maxima**. Under independent continuous draws, ten calls have a 59.9% chance (`.95^10`) of never reaching the population's upper 5%. A single long pause can instead set the entire process statistic. Five maxima are not a p95 of fifty independent calls. JIT, GC and shared host conditions also undermine independence.

Window p95s from `summary.generation` in local `test-results/ef-checkpoint/original/docs/ef0-evidence/native-{1,2,3,4}.json` illustrate both problems (ms, rounded):

| Seed | Initial 1 / 2 | Retry 3 / 4 |
| --- | ---: | ---: |
| MOURNING-731 | 69.900 / 69.233 | 103.101 / 87.338 |
| trial-23 | 247.660 / 246.418 | 410.938 / 288.535 |
| trial-27 | 64.543 / 62.381 | 107.780 / 74.758 |
| ember-70 | 79.124 / 79.589 | 121.063 / 88.074 |
| tribute-12 | 71.670 / 71.969 | 106.319 / 88.907 |

The retry was also under higher load. In the [last quiet pair](../../ef0-baseline.md#quiet-window-follow-up-2026-11-23), all five process-median ranges fit their additions and none of the five process-p95 ranges did. Even `tribute-12`'s window p95s (70.205 / 91.833) differed by 21.628 ms against 12.153 ms allowed. The stop was correct. The old design is under-resolved for the tail; these unpaired baseline windows cannot establish numerical power for a future paired test or prove that sample count explains all the noise. Neither pooling old cycles nor trimming pauses repairs it. Keep every old sample, interpretation and nominal cap unchanged.

## Test contract first (future implementation)

- Pure `node:test` fixtures: ranks 50 and 95 of 100, no interpolation or trimming; seed isolation; reverse execution order without reversing the sign of candidate minus baseline. A common additive block delay cancels.
- Hand-sort 16 known pair differences; check the bounds below, the absolute and percentage margin branches, exact boundary, one uncertain seed among nine passing endpoints, a clear regression and a small permissible slowdown. Reject NaN, incomplete cycles, repeated pair IDs, missing arm, wrong hashes/order and truncated files. Never substitute a successful pair for a failed one.
- Stub process/clock/filesystem for timeout, wrong working directory, existing destination and failed preflight. Assert no additional launch after stop, no write to old evidence and no benchmark on test discovery.

## Fixed protocol and acceptance criteria

1. **Freeze before collection.** Version the timing-only harness, analyzer, source/lock digests, commands, order schedule, telemetry checks and this decision rule. Use two independently materialized roots of the frozen `398a1cf` kit for A/A; identical Node 26.0.0, flags, dependencies, host and warm filesystem policy. No profiler, browser, build, forced GC, affinity, priority, governor or other system changes. Record host/power identity, start/end load and read-only runnable/idle and thermal observations. Book quiet slots before inspecting timings; abort for a competing build/benchmark, changed host configuration or observed throttling, not because a duration looks bad.
2. **Unit of comparison:** 16 scheduled blocks per phase, each in a separately scheduled quiet window with two adjacent sequential fresh processes, one per root. Balance which root goes first (shuffle eight AB and eight BA labels once and archive the schedule before running). Separate windows to sample independent host episodes; adjacent arms share short-term conditions. Each process uses the same two warm cycles, same five seeds in table order, default options, then **100** timed rotations. Per seed report nearest-rank median and p95 (95th, with five larger observations possible, rather than the maximum). Keep all cycles, including GC pauses. This estimates a typical paired change in a warmed process statistic, not a worst-process guarantee. Never treat 100 cycles or five seeds as independent process replicates.
3. **EF0 now: demonstrate resolution on identical code.** For each of ten endpoints (five seeds × two ranks), let `B` be the median of the 16 designated reference-arm process statistics (average middle two). Freeze B in ms and its original addition `M = max(2 ms, 0.10 B)` for median or `max(5 ms, 0.15 B)` for p95. As a safeguard against buying headroom from a slower session, cap M at the corresponding addition from the original unrounded initial midpoint (derive from native-1/2); never promote the old nominal absolute cap to a qualified result. Publish B, M and B+M, without rounding in the decision. Compute the 16 within-block pseudo-candidate minus reference differences, sort ascending, and require **both** `d[5] >= -M` and `d[12] <= M` (one-based) for every endpoint. Publish arm summaries, all differences and bounds even on failure. This checks that the design can resolve zero change against the actual budgets; it is not evidence about Effect.
4. **Why these bounds:** for independent representative pairs with common median difference, the sign-test upper bound `d[12]` has at least 96.16% one-sided coverage (`P(Binomial(16, .5) >= 12) ≈ .0384`); `d[5]` is its lower counterpart. These are individual one-sided bounds, not a simultaneous 96% confidence band. Requiring *all* upper bounds to pass tests the global claim that no endpoint exceeds its margin: if even one exceeds it, a false global pass requires falsely passing that endpoint. No averaging across seeds. Sixteen pairs allow four high-side exceptions without discarding data; if the probability of landing within the upper margin is .9 per independent pair, the chance of at least 12 of 16 is about .98 **for that endpoint**, not a promised joint power. Show differences by time and arm order. If common conditions/independence are not credible (e.g. sustained drift or order-dependent signs), block rather than claim this coverage.
5. **EF4 only:** repeat that fixed 16-block design once, now frozen source vs identified candidate, with the same harness, settings and frozen millisecond margins. Do not compare a lone candidate window to a historical point. Verify matched controls: if the concurrent reference median for any endpoint differs from frozen B by more than M, declare unmatched/inconclusive, never rebase. For each endpoint compare the paired candidate-minus-reference upper bound to M. All ten `d[12] <= M` → timing non-regression demonstrated. Any `d[5] > M` → evidence of an over-budget endpoint (report individual bounds); otherwise a nonpassing comparison is inconclusive. Neither outcome permits adoption. Zero or a modest positive difference is fine; absence of a significant difference from zero is not a pass. Correctness, allocation, cold import/native startup, bundle, resources and qualified animation (4.510 ms displayed) retain their separate [original gates](../../ef0-baseline.md); a timing pass alone cannot adopt the candidate.
6. **Stop and retain.** One campaign per phase, at most 32 processes / 16,000 measured worlds per campaign; 180 s per process, two-hour total active deadline and a seven-day scheduling cutoff per phase. Missing slot, timeout, invalid pair, insufficient precision or failed qualification ends the phase blocked, with partial data retained. No reruns, optional stopping for success, extra cycles, alternate quantiles, favorable window selection or budget edits. Archive cycle-level timings, pair/arm labels, timestamps, commands, hashes, environment, telemetry, errors and replayable report in a new write-once evidence directory. Independent review of complete A/A evidence and the other EF0 prerequisites is required before EF1; if unavailable or unsuccessful, **no defensible timing clearance**. No baseline-only result decides adoption.
